# 企业级智能问数产品实施计划

## Context

`E:\my_proj\datagent_demo` 当前为空。目标不是 MVP，而是交付一套可在企业内网投入使用的智能问数产品：支持 Excel/CSV、PostgreSQL、MySQL、ClickHouse，具备统一指标口径、权限与审计、多轮分析、仪表盘、导出与定时报表，以及准确率评测和运营监控。

已确认边界：单企业、多部门/项目工作区；50 人以内、约 10 路并发；OIDC/SSO；已有内网 OpenAI 兼容模型接口，可接入自建 DeepSeek/Qwen；数据与模型请求不出内网；目标部署为 Docker Compose。**不接入 Claude 或其他外部模型 API。**

版本管理使用 `https://github.com/simple123456T/claude_agent_demo.git`，本地目录初始化为 Git 仓库，默认分支 `main`，远程名 `origin`。已检查远程没有 refs；首次提交只包含经批准的计划、产品文档、工程配置和后续代码，不包含秘密或业务数据。

## 一、总体架构

采用**模块化单体后端 + 独立任务 worker**，避免过早微服务化，同时保证模块边界、测试和后续拆分能力。

- 前端：React + TypeScript + Vite + Ant Design + ECharts，全部静态资源本地打包，不依赖公网 CDN。
- 后端：Python、FastAPI、SQLAlchemy 2、Pydantic；Docker 内使用稳定 Python 版本。
- 模型：官方 OpenAI Python SDK 指向内网 `base_url`，适配 DeepSeek/Qwen；模型名、路由、超时、重试和结构化输出能力均可配置。
- 控制面：PostgreSQL 保存用户、工作区、语义版本、会话、任务、审计和评测；Milvus 用于可选语义向量检索，不承载权限事实。
- 协调与制品：Redis 用于队列/短期缓存，MinIO 私有保存原始上传、Parquet 数据集和导出文件。
- 任务：Celery worker/beat；PostgreSQL 是任务事实源，事务 outbox 负责可靠投递，所有任务支持幂等、租约、心跳、取消和重试。
- 可观测性：OpenTelemetry + Prometheus/Grafana，日志与追踪通过 Compose profile 启用；告警覆盖失败率、延迟、队列积压、模型异常和数据源异常。
- 部署：Nginx 入口、backend、worker、frontend、PostgreSQL、Redis、Milvus、MinIO；提供备份恢复、迁移、升级回滚和离线镜像清单。
- 本地开发使用用户已提供的 PostgreSQL 19、Redis 7、Milvus 3.0.5 服务，地址均为 `127.0.0.1`；真实密码仅存于被 Git 忽略的 `.env`，示例配置不保存真实凭据。

## 二、核心原则：语义计划优先，而非模型自由写 SQL

### 1. 版本化语义层

数据 Steward 可维护：

- 数据集、业务实体、字段、同义词、数据分级和负责人。
- 表关系、JOIN 类型、关系基数、主外键和扇出风险。
- 指标公式、聚合方式、可加总性、空值规则、单位、时区和口径版本。
- 维度、时间粒度、层级、默认过滤和敏感列策略。
- 派生指标、同比/环比、去重计数、窗口、TopN、子查询和集合操作。
- 复杂指标使用经审核、版本化、参数化的 SQL 模板；模板不接受模型注入任意 SQL。

### 2. 受限 QuerySpec

模型只输出结构化查询计划：数据集、指标、维度、关系、过滤、时间范围、比较、排序和限制。标识符必须引用调用者有权看到的语义注册表，**不接受 SQL 片段或表达式字符串**。

编译链路：

`用户问题 → 权限内语义检索 → QuerySpec → Pydantic/语义校验 → 必要澄清 → 逻辑计划 → 行列权限重写 → SQLGlot 方言 AST → 只读/函数白名单/代价检查 → 执行`

QuerySpec 无法表达或业务含义不明确时，系统澄清或明确拒答，并引导补充语义定义；不通过自由 SQL 绕过能力边界。

### 3. 权限必须在编译前生效

- 行策略绑定到每个关系，在 JOIN、聚合、子查询之前注入，防止通过聚合或计数推断隐藏数据。
- 列权限同时约束投影、表达式、过滤、JOIN、GROUP BY、HAVING、ORDER BY 和子查询；默认拒绝，支持脱敏列。
- 最终 AST 只接受单条只读查询，拒绝 DML/DDL、`SELECT INTO`、多语句、危险函数和未批准表函数。
- PostgreSQL/MySQL/ClickHouse 使用各自方言编译与真实实例测试，不依赖三种数据库各自的 RLS 行为保持一致。
- 数据库连接仍必须使用最小权限只读账号，并设置行数、字节、并发、连接/执行超时及方言级扫描代价限制。

## 三、产品功能模块

### 身份、工作区与权限

- OIDC Authorization Code + PKCE；后端校验 JWKS、issuer、audience、签名和过期时间。
- HttpOnly/Secure/SameSite 会话，严格 CORS/CSP/CSRF 防护；初始管理员通过一次性 OIDC subject 配置引导。
- 角色：组织管理员、工作区管理员、数据 Steward、分析师、查看者；OIDC 用户组可映射角色。
- 所有资产携带 `workspace_id`，服务端注入身份上下文；PostgreSQL 控制面 RLS 作为第二道隔离。
- 数据源、语义模型、查询、导出、订阅、审计分别授权；权限变更有版本并立即使相关缓存失效。

### 数据源与文件数据集

- 管理 PG/MySQL/ClickHouse 连接、连接测试、定时 schema 同步、健康状态和数据负责人。
- 提供数据画像和质量规则：缺失、重复、异常值、新鲜度、行数波动与分布变化；数据集展示质量状态，关键规则失败时阻止发布或对答案明确降级提示。
- schema 同步生成结构化差异，识别字段删除/类型变化/关系变化对指标、收藏、仪表盘和评测集的影响；变更需 Steward 审核并触发相关回归。
- 密码与 OIDC secret 使用信封加密，主密钥从 Docker secret/环境注入，支持轮换；日志和 API 永不返回秘密。
- 连接与模型/OIDC 外呼均使用内网主机 allowlist，阻止云 metadata、未授权回环地址和任意外联。
- CSV/XLS/XLSX 上传进入私有暂存区，检查真实格式、大小、解压后大小、行列数、宏和压缩炸弹；解析进程设置资源限额。
- 用户确认字段类型、时区和表头后发布为版本化 Parquet/DuckDB 数据集；原始文件和派生文件按工作区隔离。

### 问数与分析体验

- 对话式问数、条件澄清、结构化多轮上下文、历史 QuerySpec 追问修改。
- 展示“答案证据卡”：业务口径、来源表、过滤条件、QuerySpec、语义/权限版本、SQL（按权限）、执行状态、行数、耗时、数据新鲜度和截断状态；支持一键反馈错答并关联完整证据。
- 回答只基于真实返回结果；空结果、截断、部分失败和无法回答均有明确状态，不编造数字。
- 复杂分析采用可复现工作流：基线对比 → 维度拆解 → 贡献度排序 → 异常识别 → 继续下钻；每一步保存独立 QuerySpec、输入和结果，允许用户回到任一步修改条件。
- 归因结果区分“数据事实”“统计异常”和“待验证假设”；没有实验或因果依据时不输出确定性因果结论。
- 自动 stat/折线/柱形/条形/表格，保留图例、tooltip、可访问表格和空状态；不使用双轴或未经控制的饼图。
- 收藏问题、保存分析、仪表盘布局、全局筛选、分享与版本历史；分享不复制权限，访问时重新鉴权。

### 导出、订阅与定时报表

- CSV/XLSX 异步流式导出，限制行数/大小，Excel 防公式注入，明确编码、时区、精度和空值。
- 私有 MinIO 制品、短期签名链接、下载时重新鉴权、过期清理；权限撤销后历史链接立即不可用。
- 调度支持时区/DST、错过触发、补跑、取消、重试和幂等；负责人停用后自动停用。
- 邮件/受控 webhook 默认发送下载链接而非数据附件；发送前按当前权限重新执行同一查询管线。
- Celery/Redis 不作为任务完成的事实依据；worker 崩溃、重复投递和重启恢复均有测试。

### 质量与运营

- 黄金问题集绑定固定数据快照、预期 QuerySpec/结果、数值容差和权限上下文。
- 分开统计 QuerySpec 有效率、执行成功率、**结果正确率**、端到端成功率、正确澄清/拒答率；超时和失败不剔除分母。
- 训练/验证/隐藏测试集分离，多次运行并报告波动；LLM 评审仅辅助，确定性结果对比为主。
- badcase 记录责任人、模型/提示词/语义版本、分类、修复和回归状态；模型或语义变更必须跑回归。
- 监控排队、模型、编译、数据库执行、导出各阶段延迟，以及每个正确完成任务的模型 token/资源成本。
- 审计采用专用追加写入路径和受限数据库角色，覆盖登录、授权变更、查询、下载、导出、订阅及管理操作；支持导出到 SIEM。

## 五、实施阶段与验收门槛

### 阶段 0：产品契约与威胁模型

完成语义能力矩阵、权限矩阵、数据分级、SLO、页面原型、黄金问题和“不支持时如何响应”。

**门槛：**业务负责人确认黄金问题及预期结果；安全负责人确认越权、导出、缓存、任务和模型威胁场景。未定义口径的指标不进入自动问数。

### 阶段 1：企业控制面底座

完成代码工程、OIDC、工作区/RBAC、审计、密钥、迁移、任务事实源、MinIO、监控和 Compose 骨架。

**门槛：**跨工作区访问默认拒绝；秘密不泄漏；任务重启可恢复；备份恢复和迁移回滚演练通过；所有外呼目标受控。

### 阶段 2：语义内核与四类数据源

先不接模型，直接以 QuerySpec 驱动编译执行；完成三种数据库连接、文件发布、数据质量规则和 schema 漂移影响分析。

**门槛：**真实目标版本数据库的黄金查询结果一致；复杂 JOIN/子查询/聚合的行列权限测试通过；写入、多语句、危险函数和超代价查询全部被拒绝；质量异常能标记，结构变更能定位受影响资产并触发回归。

### 阶段 3：内网模型、多轮分析与资产

接入内网模型、语义检索、澄清、结构化多轮、答案证据卡、对比/拆解/贡献度分析，再完成收藏和仪表盘。

**门槛：**无效模型输出绝不进入执行；模型超时/漂移可观测；多轮指代、过滤继承和指标变更正确；复杂分析每一步可复现，事实与假设明确区分；隐藏评测集达到阶段 0 批准的正确率门槛。

### 阶段 4：导出、定时报表与质量闭环

完成异步导出、订阅、评测平台、badcase 闭环、成本延迟告警和运营页面。

**门槛：**大文件不耗尽内存；重复投递不重复发送；DST/补跑/取消正确；权限撤销后链接和调度立即失效；badcase 可回归。

### 阶段 5：生产准入

在干净的目标 Linux Compose 环境进行离线部署、10 路并发负载、worker 崩溃、Redis/MinIO/PG 异常、权限对抗、恢复和升级回滚。

**门槛：**严重越权为零；容量、正确率、延迟和任务成本达到已批准目标；RPO/RTO 演练通过；测试报告可重复执行。明确记录 Compose 单节点不等于高可用。

## 六、验证策略与当前限制

- 单元测试：QuerySpec、语义编译、行列策略、方言 AST、缓存键、权限、导出转义和调度。
- 集成测试：Testcontainers 启动 PG/MySQL/ClickHouse/MinIO/Redis；使用固定数据集验证真实 SQL 与结果，不能用 SQLite/mock 冒充数据库覆盖。
- 安全测试：跨工作区、隐藏列过滤/排序/聚合、行过滤扇出、缓存交叉命中、历史下载链接、主机 allowlist 和恶意上传。
- E2E：OIDC 登录、问数、澄清、收藏、仪表盘、导出、订阅、审计和 badcase 回归。
- 故障/负载：10 路并发、worker 杀死、消息重复、模型超时、数据库慢查询、磁盘不足和恢复演练。
- 图表：运行色板校验，使用浏览器检查桌面/窄屏、tooltip、表格替代、空数据和标签溢出。
- 当前机器**没有 Docker**，可先做本地单元测试与前端测试，但 Compose、真实数据库集成和恢复验收必须在安装 Docker 的 Linux 环境完成，不能宣称已经通过。
- 接入真实内网模型需要后续通过本地私密配置提供 `base_url`、模型名和凭据；不在对话或仓库中写入密钥。未取得端点前只运行 mock/契约测试，并明确模型准确率尚未实测。
