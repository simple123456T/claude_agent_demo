# 开发状态

## 已完成并验证

**工程基线**：配置与秘密分离、PostgreSQL / Redis / Milvus 连接探测、QuerySpec 编译与只读校验。

**企业控制面**：Alembic 迁移；只能追加的审计表（触发器拒绝改删）；OIDC 令牌校验（拒绝 `alg=none`、HS256 算法混淆）；未配置登录时受保护接口返回 503；工作区 RBAC（查看者 < 分析师 < 数据负责人 < 工作区管理员，组织管理员只有治理权限、没有数据权限）；不可见工作区返回 404；保护最后一名工作区管理员。

**问数链路**

- 手动构建与自然语言两条入口走同一条管线：规划（仅自然语言）→ 权限校验 → 确定性编译 → 独立只读复核 → 只读事务 + 语句超时 → 摘要 / 图表建议 / 查询依据。
- 前端：登录页、问数页（快捷查询、手动构建、自然语言输入）、结果卡片（摘要 / 图表 / 表格 / 依据 / CSV 导出）、系统概览页。
- 图表：折线 / 柱状 / 数字卡 / 表格自动选择；多指标分图绘制，不做双轴；类别名在 tooltip 中转义，防 XSS。
- 截断判断：多取 1 行确认数据库是否还有更多行；排行榜只显示前 N 条属正常，不报警，并且不会在被截断时声称"最低的是 X"。
- 查询审计：记录问题、结构化查询、行数、耗时、语义版本，不记录结果数据；失败也会留痕。

## 尚未验证 / 已知缺口

- **自然语言提问没有用真实内网模型验证。** 完整流程只用模拟模型测试过（有效输出、需澄清、不支持、修复一次、无法修复、模型不可用）。真实 DeepSeek / Qwen 的 JSON 输出稳定性、中文问题理解准确率**未知**，需要提供模型地址后用黄金问题集评测。
- 拼音输入法下回车只"确认候选词"而不发送：代码已处理 `isComposing`，但**没有在真实输入法下实测**。
- 前端没有自动化测试框架；浏览器验证是手工驱动的一次性脚本，没有纳入仓库。
- 开发登录令牌随后端重启失效（密钥在内存中）。这是有意的简化，不影响生产（生产走真实 OIDC）。
- 授权策略 `resolve_policy` 目前是占位：数据集所有列可读、无行过滤。编译器已能强制执行任何策略，但还没有策略管理界面和存储。
- 受治理的查询目前与控制面共用同一个 PostgreSQL 连接账号；接入真实数据源时必须换成每个数据源独立的只读账号。
- 仅支持 PostgreSQL 方言的真实执行；MySQL / ClickHouse 只验证了 SQL 文本生成，**没有连接真实实例**。
- 没有 Docker，Compose 部署未实测。

## 阶段 1 剩余项

- 任务事实源（状态机、幂等键、租约、outbox）、MinIO 私有存储、监控。
