# QuerySpec 与语义编译规范 v0.1

## 非目标

QuerySpec 不是另一种自由 SQL。模型不能提交表达式字符串、表名、物理字段、函数名或方言片段，只能引用其有权限访问的语义对象。

## 当前支持

- 单数据集、已注册维度和基础聚合指标。
- `sum`、`count`、`count_distinct`、`avg`、`min`、`max`。
- 比较、IN、空值过滤，输出排序和最大 500 行限制。
- 行策略在基础子查询中执行，用户过滤和聚合在外层执行。
- PostgreSQL、MySQL、ClickHouse 方言文本生成与独立只读复核。

## 校验顺序

1. Pydantic 拒绝未知字段、重复投影和非法过滤结构。
2. 语义注册表验证数据集、指标、维度及版本。
3. 策略验证所有用户可见列；隐藏列不得进入用户过滤或排序。
4. 将受信任的行策略注入基础关系，再构建用户查询。
5. 限制行数并生成方言 SQL。
6. `validate_read_only` 再次检查单语句、只读、系统表、函数和 LIMIT。

## 后续扩展约束

多跳 JOIN、派生指标、时间比较、窗口与 SQL 模板必须扩展 QuerySpec 和确定性编译器，不能通过给模型增加 `raw_sql` 字段实现。复杂模板只允许 Steward 审核、参数化并版本化。

## 当前明确不支持

任意表达式、模型指定物理表、跨数据集关系、时间粒度、同比环比、窗口函数和真实数据库执行。遇到这些请求应返回“不支持”，不能伪造支持。
