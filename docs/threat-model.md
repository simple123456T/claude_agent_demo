# 威胁模型（初版）

## 信任边界

浏览器、模型输出、上传文件、业务数据库内容和任务消息都按不可信输入处理。OIDC、模型网关和数据源地址必须由管理员配置并受内网 allowlist 约束。

## 重点威胁与控制

| 威胁 | 必须实施的控制 |
|---|---|
| 模型生成写入或危险函数 | QuerySpec 不含 SQL；确定性编译；独立 AST 只读复核；数据库只读账号 |
| 隐藏列通过过滤、排序或聚合泄露 | 默认拒绝；所有引用位置统一授权；权限对抗测试 |
| 行权限在 JOIN 后造成重复或泄露 | 在每个基础关系进入 JOIN/聚合前应用策略 |
| 跨工作区读取缓存或制品 | 工作区与策略指纹进入缓存键；对象私有；下载重新鉴权 |
| 恶意 Excel/CSV | 私有暂存、真实格式检查、大小/解压/行列限制、资源隔离、公式与宏控制 |
| 数据源配置造成 SSRF | 管理权限、主机 allowlist、重定向限制、云 metadata 阻断 |
| 任务重复导致重复发送 | PostgreSQL 事实源、幂等键、outbox、发送去重 |
| 权限撤销后历史链接仍有效 | 下载和调度运行时重新鉴权；权限版本使缓存失效 |
| 审计被普通管理员篡改 | 专用追加写入角色、受限数据库权限、审计导出 |
| 日志泄漏连接串或结果 | SecretStr、结构化错误分类、禁止记录秘密和结果正文 |

## 上线阻断条件

任何跨工作区读取、行列权限绕过、未授权导出、任意外联或真实秘密进入 Git 都属于发布阻断问题。Docker Compose 可用不等于这些威胁已经验证，必须保留可重复的测试证据。
