# 产品需求与验收边界

## 目标用户

- 分析师：自然语言问数、多轮拆解、收藏与仪表盘。
- 查看者：查看被授权的分析与报表，不管理语义和连接。
- 数据 Steward：维护数据集、指标、关系、质量规则和权限策略。
- 工作区管理员：管理成员、数据源、分享、导出和订阅。
- 组织管理员：身份、全局安全、审计与系统运维。

## 核心场景

1. 用户询问已发布指标，系统返回真实结果、口径、来源和过滤条件。
2. 指标或术语存在多种解释时，系统先澄清，不选择任意口径执行。
3. 用户追问“按区域拆解”“与上月相比”，系统基于上一版 QuerySpec 修改，而不是拼接整段聊天。
4. 用户只能看到当前工作区和权限范围内的数据；导出、下载、分享、订阅重新鉴权。
5. Steward 能定位错答属于模型、语义、数据质量、权限还是执行问题，并加入回归集。

## 能力边界

系统优先回答已发布语义模型能够表达的问题。没有口径、权限或数据依据时必须澄清或拒答，不允许模型用自由 SQL 绕过治理。

## 正式验收前需要企业提供的输入

- 20–50 个高频黄金问题及业务预期答案，逐步扩充隐藏测试集。
- 指标负责人、业务术语、数据关系、时区和空值规则。
- 角色、部门、行列权限和导出规则的样例矩阵。
- 内网模型接口、OIDC 测试环境和真实目标版本数据库。
